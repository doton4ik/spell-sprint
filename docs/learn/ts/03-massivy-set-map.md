# Урок 3. Массивы, `Set` и `Map`

Цель: читать код, который считает, фильтрует и группирует списки. Такого кода в проекте больше всего: статистика,
серия дней, списки слов и ошибок.

## 3.1 Массив

**Массив** — упорядоченный список значений одного типа.

```ts
const words: string[] = ['cat', 'dog', 'bird']      // string[] = "массив строк"
words[0]            // 'cat'  (нумерация с нуля)
words.length        // 3
```

Запись `string[]` то же самое, что `Array<string>` (в проекте встречаются обе).

## 3.2 Методы массива: `map`, `filter`, `some`, `reduce`

Вместо цикла `for` чаще используют методы. Каждый принимает **функцию** и применяет её к каждому элементу.

| Метод | Что делает | Возвращает |
|---|---|---|
| `map(f)` | превращает каждый элемент | новый массив той же длины |
| `filter(f)` | оставляет элементы, для которых `f` дало `true` | новый, короче или равный |
| `some(f)` | есть ли хоть один подходящий | `true` / `false` |
| `every(f)` | подходят ли все | `true` / `false` |
| `find(f)` | первый подходящий | элемент или `undefined` |
| `reduce(f, start)` | сворачивает всё в одно значение | одно значение |
| `sort(f)` | упорядочивает | тот же массив (меняет его!) |
| `slice(a, b)` | кусок массива | новый массив |

Теперь реальный код. Откройте `src/components/practice/SessionRails.tsx`:

```ts
const results = tasks.map((task) => outcomes[task.id])
const correct = results.filter((outcome) => outcome === 'correct').length
const missed = results.filter((outcome) => outcome === 'incorrect' || outcome === 'skipped').length
```

Читаем по строкам:

1. `tasks` — список заданий сессии. `map` превращает каждое задание в его результат из словаря `outcomes`
   (например `'correct'`). Получился список результатов, того же размера, что и заданий.
2. `filter` оставляет только `'correct'`, `.length` считает, сколько их. Это и есть счётчик «верно».
3. Для «пропущено» условие сложнее: ошибка **или** пропуск. `||` читается «или», `&&` — «и».

Функция `(outcome) => outcome === 'correct'` называется **колбэком**: её передают в метод, и он вызывает её для
каждого элемента.

### Цепочки

Методы можно соединять, потому что каждый возвращает новый массив:

```ts
const weak = getTopicStats()
  .filter((topic) => topic.due > 0)          // только темы со словами на повтор
  .sort((a, b) => b.due - a.due)             // сначала где их больше
  .slice(0, 5)                               // первые пять
```

Это код из `src/components/ui/PageRails.tsx` (карточка «Waiting for review» на странице «Темы»).

Про `sort((a, b) => b.due - a.due)`: функция получает два элемента и возвращает число. Если результат
отрицательный, `a` идёт раньше, если положительный — `b`. Разность `b.due - a.due` ставит **большие значения вперёд**
(порядок по убыванию). Для порядка по возрастанию пишут `a.due - b.due`.

Осторожно: `sort` меняет сам массив. Поэтому перед ним часто делают копию: `[...topics].sort(...)`. Три точки
перед именем (**spread**) разворачивают массив в новый.

## 3.3 `Set`: набор уникальных значений

`Set` не хранит повторы. Откройте `src/services/dailyPlan.ts`, функцию `getStreak` (серия дней):

```ts
const days = new Set(attempts.map((attempt) => localDayKey(attempt.createdAt)))
const today = new Date()
let cursor = days.has(localDayKey(today)) ? today : shiftDay(today, -1)
let streak = 0
while (days.has(localDayKey(cursor))) {
  streak += 1
  cursor = shiftDay(cursor, -1)
}
return { streak, practisedToday: days.has(localDayKey(today)) }
```

Идея алгоритма:

1. Каждый ответ превращают в «ключ дня» (`'2026-10-12'`, урок 1) и складывают в `Set`: за день 50 ответов — в наборе
   одна запись.
2. Начинают с сегодняшнего дня, а если сегодня ещё ничего не решали, то со вчерашнего (серия не пропадает до конца
   дня).
3. Пока этот день есть в наборе, добавляют единицу и шагают на день назад. Первый день без ответов останавливает цикл.
4. Возвращают объект с двумя полями: длина серии и «занимался ли сегодня».

`days.has(x)` — быстрая проверка «есть ли такое значение». У массива такая проверка (`includes`) медленнее.

`while (условие) { … }` — цикл «пока верно». `streak += 1` — то же, что `streak = streak + 1`.

## 3.4 `Map`: словарь «ключ → значение»

`Map` хранит пары. Удобно считать и группировать. Откройте `PageRails.tsx`, `SprintRail` (карточка «Slowest to type»):

```ts
const byWord = new Map<string, { total: number; count: number }>()
for (const round of getSprintRounds().slice(0, 10))
  for (const answer of round.answers) {
    if (!answer.correct || answer.typeMs <= 0) continue
    const entry = byWord.get(answer.word) ?? { total: 0, count: 0 }
    entry.total += answer.typeMs
    entry.count += 1
    byWord.set(answer.word, entry)
  }
return [...byWord.entries()]
  .map(([word, { total, count }]) => ({ word, seconds: total / count / 1000 }))
  .sort((a, b) => b.seconds / b.word.length - a.seconds / a.word.length)
  .slice(0, 5)
```

Разбор:

1. `new Map<string, {...}>()` — словарь: ключ слово, значение сумма времени и число попыток. В угловых скобках
   указывают типы ключа и значения (это **дженерик**, урок 5).
2. Берут последние 10 раундов и в каждом перебирают ответы циклом `for … of`.
3. `if (...) continue` — пропустить неподходящий ответ (неверный или без времени набора).
4. `byWord.get(слово) ?? { total: 0, count: 0 }` — достать запись или, если слова ещё нет, начать новую. Знак `??`
   означает «если слева ничего (`null`/`undefined`), то справа» (урок 4).
5. Накапливают сумму и счётчик, кладут обратно (`set`).
6. `[...byWord.entries()]` — словарь превращают в массив пар `[слово, {total, count}]`. В `map` пара разбирается сразу
   на части: `([word, { total, count }]) =>` (**деструктуризация**).
7. Считают среднее время в секундах, сортируют по «секунд на букву» (длинные слова не должны выглядеть медленными
   только из-за длины) и берут пять.

Паттерн «пройти по списку, накопить в `Map`, превратить в массив, отсортировать» очень частый. Запомните его.

## Вопросы на понимание

1. Что вернёт `[1, 2, 3, 4].filter((n) => n % 2 === 0).map((n) => n * 10)`?
2. Почему в `getStreak` ключи дней складывают в `Set`, а не в обычный массив?
3. Как работает условие `days.has(localDayKey(today)) ? today : shiftDay(today, -1)` и почему серия не обнуляется утром,
   пока вы не начали заниматься?
4. В чём разница между `a.due - b.due` и `b.due - a.due` в `sort`?
5. Что делает строка `byWord.get(answer.word) ?? { total: 0, count: 0 }`? Что было бы без `?? …`?
6. Зачем в `SprintRail` сортируют по «секунды на букву», а не по секундам?
7. Почему `[...topics].sort(...)` безопаснее, чем `topics.sort(...)`?
8. Как с помощью `reduce` посчитать сумму массива чисел `[3, 5, 2]`? (Подсказка: `reduce((sum, n) => sum + n, 0)`.)

<summary>Ответы (откройте после своих)</summary>

1. `[20, 40]`. Сначала остаются чётные (2 и 4), затем каждое умножается на 10.
2. `Set` не хранит повторы: за день могут быть десятки ответов, но нужен сам факт «день был». Проверка `has` быстрая и
   читается как «есть ли такой день».
3. Если у сегодняшнего дня ответы есть, начинаем с него, иначе со вчерашнего. Утром сегодняшних ответов ещё нет,
   считаем от вчера, и серия остаётся, пока не кончится сегодняшний день. Серия рвётся, только если не было ответов
   и вчера.
4. `a.due - b.due` ставит меньшие значения первыми (по возрастанию), `b.due - a.due` — большие первыми (по убыванию).
5. Берёт запись по слову, а если её нет (`undefined`), создаёт пустую со счётчиками по нулю. Без этого код упал бы на
   `entry.total` у несуществующей записи (TypeScript показал бы здесь ошибку про возможный `undefined`).
6. Чтобы длинные слова не выглядели медленными только из-за длины. Скорость набора сравнивают на одну букву.
7. `sort` меняет исходный массив. Копия `[...topics]` оставляет оригинал нетронутым: иначе порядок меняется там, где
   его никто не просил.
8. `[3, 5, 2].reduce((sum, n) => sum + n, 0)` даёт `10`. Начальное значение `0`, на каждом шаге к накопленной
   сумме добавляется элемент.
