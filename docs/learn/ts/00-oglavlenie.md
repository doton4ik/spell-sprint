# TypeScript на примере Spell Sprint

Восемь уроков. Каждый разбирает настоящий код проекта: вы читаете то, что реально работает в приложении, а не
учебные примеры про «собак и кошек». После каждого урока есть вопросы на понимание. Ответы лежат в конце файла,
под спойлером, поэтому сначала подумайте сами.

| # | Урок | Главные файлы проекта |
|---|---|---|
| 1 | Типы и функции | `src/services/dateKeys.ts`, `contractions.ts` |
| 2 | Объекты, `type`, строковые варианты | `src/types/practice.ts`, `data/levelCheckBank.ts` |
| 3 | Массивы, `Set`, `Map` | `services/dailyPlan.ts`, `components/ui/PageRails.tsx` |

## Как учиться

1. Откройте файл из урока в редакторе рядом с текстом. Найдите кусок кода сами, а потом сверяйтесь с разбором.
2. Игрушечные примеры пробуйте на странице <https://www.typescriptlang.org/play> (она ничего не ломает). Проект
   трогать для учёбы не нужно.
3. Чтобы увидеть, как TypeScript находит ошибки в проекте, запускайте в папке проекта:

   ```bash
   pnpm exec tsc -b
   ```

   Пустой вывод значит «ошибок нет». Эта же проверка входит в `pnpm check`.
4. Отвечайте на вопросы письменно, хотя бы в голове, прежде чем открывать ответ. Если не получилось, перечитайте
   раздел и попробуйте снова.

## Как TypeScript связан с JavaScript

TypeScript — это JavaScript плюс **типы**. Тип отвечает на вопрос «что за значение здесь лежит» (строка, число, список
чего-то). Браузер типов не понимает: при сборке проекта их стирают, остаётся обычный JavaScript. Типы нужны
вам и редактору: они находят ошибки **до запуска** программы, подсказывают поля объекта и защищают от опечаток.

Пример опечатки, которую находят типы: если в коде написать `attempt.isCorect` вместо `attempt.isCorrect`, JavaScript
молча вернёт `undefined` и ошибка проявится где-то позже, а TypeScript сразу подчеркнёт слово красным.
