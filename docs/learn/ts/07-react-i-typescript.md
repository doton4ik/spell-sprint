# Урок 7. React и TypeScript

Цель: читать компонент, понимать откуда в нём берутся данные и что происходит при нажатии кнопки.

## 7.1 Идея React

Экран собирают из **компонентов**. Компонент — это функция, которая получает данные и возвращает описание того, что
нужно нарисовать. React сам следит, когда данные поменялись, и перерисовывает только нужное.

Файлы страниц лежат в `src/pages/`, мелкие кусочки — в `src/components/`. Файлы компонентов заканчиваются на `.tsx`:
`x` значит, что внутри можно писать **JSX** (HTML-подобную запись прямо в коде).

## 7.2 Первый компонент

Откройте `src/components/ui/PageRails.tsx`. Самый маленький компонент в нём:

```tsx
function RailRow({ name, value }: { name: string; value: string }) {
  return (
    <p className="rail-row">
      <span>{name}</span>
      <strong>{value}</strong>
    </p>
  )
}
```

Читаем:

- `function RailRow(...)` — компонент это обычная функция, имя **с большой буквы** (так React отличает его от тега).
- `{ name, value }: { name: string; value: string }` — **props** (входные данные). Слева деструктуризация (урок 3),
  справа тип: у компонента два обязательных строковых параметра.
- `return ( … )` — JSX. Это не строка, а описание элементов: абзац `<p>` с двумя вложенными.
- `className` вместо `class` (в JS слово `class` занято).
- В фигурных скобках `{name}` вставляется значение из JavaScript.

Использование:

```tsx
<RailRow name="Day streak" value="12" />
```

Если забыть `value` или передать число, TypeScript подчеркнёт ошибку: компонент объявил, что хочет строку.

### Вложенность и `children`

```tsx
function RailCard({ label, children }: { label: string; children: ReactNode }) {
  return (
    <section className="rail-card">
      <span className="rail-card__label">{label}</span>
      {children}
    </section>
  )
}
```

`children` — всё, что вложено между тегами при использовании:

```tsx
<RailCard label="Missed most often">
  <RailRow name="Articles" value="3×" />
  <RailRow name="Prepositions" value="2×" />
</RailCard>
```

Содержимое между тегами попадает в `children`. Тип `ReactNode` означает «что-то, что React умеет рисовать»
(текст, элемент, список, пусто).

## 7.3 Список и `key`

Как нарисовать список? Превратить массив в массив элементов (метод `map` из урока 3):

```tsx
{slow.map((item) => (
  <RailRow key={item.word} name={item.word} value={`${item.seconds.toFixed(1)} s`} />
))}
```

`key` — уникальная метка элемента среди соседей. По ней React отличает «этот же элемент» от нового при перерисовке.
Берут стабильный уникальный идентификатор (слово, `id`), а **не номер в списке**, если список может менять порядок.

## 7.4 Условное отображение

В JSX нельзя писать `if`, но можно использовать выражения:

```tsx
{missedTasks.length ? <div>…список…</div> : null}
{accuracy.percent !== null ? <RailRow name="Accuracy, 30 days" value={`${accuracy.percent}%`} /> : null}
```

Если условие ложно, возвращается `null`, и React ничего не рисует. Целый компонент тоже может вернуть `null`:

```tsx
export function SprintRail() {
  ...
  if (slow.length < 3) return null
  return ( … )
}
```

Так карточка «Slowest to type» **не рисуется**, пока данных мало. Мы специально так делали: если сказать нечего, место
пустое лучше, чем «0».

## 7.5 Состояние: `useState`

Данные, которые меняются и от которых зависит внешний вид, хранят в **состоянии**. В `PracticePage.tsx` строка «All
libraries · 10 words · Write in English · Change» открывает списки настроек по нажатию «Change»:

```tsx
const [setupOpen, setSetupOpen] = useState(false)
...
<button type="button" onClick={() => setSetupOpen((open) => !open)}>
  {setupOpen ? 'Done' : 'Change'}
</button>
...
{setupOpen ? <div className="practice-filters">…</div> : null}
```

- `useState(false)` создаёт состояние с начальным значением `false`. Возвращает пару: **текущее значение** и
  **функцию, которая его меняет**. Запись `const [a, b] = …` — деструктуризация массива.
- `onClick={() => …}` — обработчик нажатия. Функция выполнится, когда нажмут кнопку.
- `setSetupOpen((open) => !open)` — «поменяй на противоположное»: `!` превращает `true` в `false` и обратно.
- Когда состояние изменилось, React **вызывает компонент заново**, `setupOpen` теперь новое, и на экране появляется или
  исчезает блок.

Главное правило: **не меняйте состояние напрямую** (`setupOpen = true` не сработает), только через функцию из пары.

TypeScript выводит тип по начальному значению (`false` → `boolean`). Если вывод не подходит, тип указывают в
угловых скобках: `useState<number | 'all'>(10)` (число или слово `'all'`).

## 7.6 `useMemo` и `useEffect`

Откройте начало `src/pages/DashboardPage.tsx`:

```tsx
const [revision, setRevision] = useState(0)
useEffect(() => subscribeToLearningData(() => setRevision((value) => value + 1)), [])
const analytics = useMemo(getLearningAnalytics, [revision])
const plan = useMemo(() => buildDailyPlan(), [revision])
```

Эти четыре строки показывают главный приём проекта. Разбор:

- `revision` — число-«версия» данных. Само по себе оно ни для чего не нужно, это **сигнал**.
- `useEffect(функция, [])` выполняет действие **после показа** компонента. Пустой список `[]` в конце значит
  «один раз при появлении». Здесь страница подписывается на изменения данных: при каждом изменении вызывается
  `setRevision(value + 1)`. Функция, которую возвращает `subscribeToLearningData`, превращается в «отписку» при
  закрытии страницы.
- `useMemo(функция, [revision])` запоминает результат дорогого подсчёта и пересчитывает его, **только когда
  `revision` изменился**. Иначе при каждой перерисовке аналитика считалась бы заново.

Сценарий: вы ответили на слово → данные изменились → подписка вызвала `setRevision` → компонент перерисовался →
`useMemo` увидел новое число и пересчитал `analytics` → на экране новая цифра.

Список в квадратных скобках в конце хуков называется **зависимостями**: «пересчитывай/выполняй заново, когда изменится
хоть что-то из этого списка».

## 7.7 Тип для props отдельно

Когда у компонента много параметров, тип выносят в `type`. `src/components/practice/SessionRails.tsx`:

```tsx
type SessionRailsProps = {
  mode: PracticeMode
  taskIndex: number
  tasks: PracticeTask[]
  outcomes: Record<string, TaskOutcome>
}

export function SessionRails({ mode, taskIndex, tasks, outcomes }: SessionRailsProps) { … }
```

Использование на странице:

```tsx
<SessionRails mode={mode} taskIndex={session.taskIndex} tasks={session.sessionTasks} outcomes={session.outcomes} />
```

Это уроки 2 и 5 в действии: типы из `types/practice.ts`, словарь `Record<string, TaskOutcome>`.
