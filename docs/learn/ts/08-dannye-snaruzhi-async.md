# Урок 8. Данные снаружи: JSON, `try/catch`, `async`

Цель: понимать, как приложение читает данные, которым нельзя доверять (хранилище браузера, база, сеть), и что
делает слово `await`. Этот урок связывает TypeScript с вашим курсом SQL.

## 8.1 Граница: где типы заканчиваются

Внутри приложения TypeScript знает форму каждого значения. Но данные приходят и **снаружи**:

- из `localStorage` браузера (там лежат строки);
- из базы Supabase (ответ сервера);
- из файлов `.json`.

Что там на самом деле, TypeScript проверить не может. Старая версия приложения, сбой записи или человек в консоли могли
положить туда что угодно. Поэтому на границе действуют три правила:

1. Считайте внешние данные недоверенными.
2. Проверяйте и приводите их к своим типам в **одном** месте.
3. Предусматривайте запасной вариант, если чтение не удалось.

## 8.2 JSON

**JSON** — текстовый формат для данных: `{"word":"cat","tries":2}`. Хранилище браузера умеет хранить только строки, поэтому
объекты превращают в текст и обратно:

```ts
const text = JSON.stringify({ word: 'cat', tries: 2 })   // '{"word":"cat","tries":2}'
const back = JSON.parse(text)                              // объект; тип неизвестен (any)
```

`JSON.parse` вернёт то, что было в строке. Если строка повреждена (оборвана запись), `JSON.parse` **бросает ошибку**.

## 8.3 `try` / `catch`: ловим ошибку

Ошибка (исключение) без обработки обрушивает ту часть программы, где произошла. `try/catch` позволяет её перехватить.
Откройте `src/services/levelCheck.ts`, функцию `getLevelChecks`:

```ts
export function getLevelChecks(): LevelCheckResult[] {
  try {
    const stored = JSON.parse(window.localStorage.getItem(HISTORY_KEY) ?? '[]') as LevelCheckResult[]
    return Array.isArray(stored)
      ? stored
          .filter((item) => item && typeof item.id === 'string' && item.skills)
          .sort((a, b) => b.completedAt.localeCompare(a.completedAt))
      : []
  } catch {
    return []
  }
}
```

Читаем:

1. Берут текст из хранилища; если там пусто (`null`), используют `'[]'` (пустой список). Это `??` из урока 4.
2. `JSON.parse` превращает текст в данные. `as LevelCheckResult[]` — заверение типа (урок 5); на самом деле тут может
   быть что угодно, поэтому ниже идёт проверка.
3. `Array.isArray(stored)` — убеждаемся, что это вообще список.
4. `filter` оставляет только записи, похожие на настоящие: есть `id` (строка) и `skills`. Мусор отбрасывается.
5. `sort` ставит свежие проверки первыми (сравнение дат как строк: формат даты такой, что порядок строк совпадает с
   порядком времени).
6. Если что-то пошло не так (`JSON.parse` упал), срабатывает `catch` и возвращается пустой список. Приложение продолжает
   работать, просто «истории нет».

Схема, которую стоит запомнить: **читаем → проверяем → при сбое возвращаем безопасное значение по умолчанию**. Страница
«Level check» не упадёт из-за испорченных данных.

### Запись тоже может не получиться

`src/services/safeStorage.ts`:

```ts
export function safeSetItem(key: string, value: string): boolean {
  try {
    window.localStorage.setItem(key, value)
    return true
  } catch (error) {
    reportError(error, `storage ${key.replace('spell-sprint.', '')}`)
    window.dispatchEvent(new Event(STORAGE_FAILED_EVENT))
    return false
  }
}
```

Запись в хранилище бывает невозможна: оно переполнено или запрещено (приватный режим, строгая настройка браузера).
Функция:

- возвращает `true`/`false` (получилось или нет), чтобы вызывающий код мог на это отреагировать;
- сообщает об ошибке в журнал (`reportError`);
- рассылает событие, чтобы оболочка приложения показала человеку предупреждение;
- **не роняет страницу**: ответ на слово всё равно остаётся на экране.

`catch (error)` даёт доступ к самой ошибке; `catch {` без скобок значит «ошибка не нужна».

## 8.4 Асинхронность: `Promise`, `async`, `await`

Некоторые действия занимают время: запрос к базе по сети. Если программа будет ждать ответ, замёрзнет страница.
Поэтому такие функции возвращают **обещание** (`Promise`): «результат будет позже». Тип `Promise<Rule[]>` читается как
«обещание списка правил».

Слово **`await`** ставят перед обещанием: «подожди результат и продолжай». Использовать его можно только внутри функции,
помеченной **`async`**.

Откройте `src/services/rulesService.ts`:

```ts
export async function getVisibleRules(): Promise<Rule[]> {
  try {
    if (!isSupabaseConfigured()) throw new Error('offline')
    const rows = await selectRows(null, 'rules', { is_active: true }, { order: 'title.asc' })
    return rows.map(toRule)
  } catch {
    return (await bundled()).rules.map(toRule)
  }
}
```

Разбор:

1. `async` + возвращаемый тип `Promise<Rule[]>`: функцию вызывают с `await`, и она вернёт список правил.
2. Если ключи Supabase не настроены, функция специально бросает ошибку `throw new Error('offline')`. Это способ быстро
   перейти в блок `catch`.
3. `await selectRows(...)` — запрос к серверу. Пока он идёт, остальное приложение работает.
4. `rows.map(toRule)` — каждую строку базы превращают в тип `Rule` (урок 5: единственное место, где используется `as`).
5. В `catch` запасной вариант: правила из файла `builtInRules.json`, который лежит прямо в приложении. Поэтому страница
   «Rules» работает и без интернета.

Так выглядит принцип **«сначала сеть, при сбое запасной вариант»**. Приложение остаётся полезным в метро.

## 8.5 Как это связано с SQL

Строка:

```ts
await selectRows(null, 'rules', { is_active: true }, { order: 'title.asc' })
```

это тот же запрос, что в SQL-курсе:

```sql
select * from public.rules where is_active = true order by title asc;
```

Приложение не отправляет SQL. Оно обращается к REST-интерфейсу Supabase (PostgREST), который по фильтрам собирает такой запрос
сам и возвращает строки в формате JSON. Результат `rows` — список объектов, по одному на строку таблицы, а ключи объектов —
имена столбцов (`rule_type`, `short_explanation`). Поэтому `toRule` и переводит их в `ruleType`, `shortExplanation`.

Заодно виден ещё один приём. Функция `selectRows` объявлена так (`src/services/supabase.ts`):

```ts
export async function selectRows<T extends TableName>(
  session: SupabaseSession | null,
  table: T,
  filters: Filters<T> = {},
  options: QueryOptions = {},
): Promise<Row<T>[]> { … }
```

Это дженерик из урока 5: `T extends TableName` значит «`T` — одно из имён таблиц». Тип фильтров и тип строки зависят
от выбранной таблицы: в `selectRows(…, 'rules', { slug })` TypeScript знает, что у `rules` есть поле `slug`, а опечатку
`{ slg }` или несуществующую таблицу не пропустит. Типы таблиц лежат в `src/types/database.ts` (их генерируют
по схеме базы командой, упомянутой в `database/README.md`).

А значение по умолчанию `filters = {}` (пустой набор фильтров) даёт необязательный параметр: можно не передавать.

## 8.6 Почему приложение читает базу с публичным ключом

В SQL-курсе (раздел 9) объяснялась защита строк (RLS). Здесь видна её другая сторона: приложение подключается с
публичным ключом (`anon`). Для публичных правил RLS разрешает читать всем, а личные таблицы (`mistake_events`) отдаёт только
владельцу. Поэтому такой код безопасен для открытого сайта. Ключ `service_role` в приложение класть нельзя: он обходит RLS.
