# Урок 1. Типы и функции

Цель: читать простую функцию и понимать, что она принимает, что возвращает и где TypeScript остановит ошибку.

## 1.1 Значения и три главных типа

У значения есть тип. Вот три самых частых:

| Тип | Примеры значений |
|---|---|
| `string` (текст) | `'cat'`, `"It's"`, `` `2026-10-12` `` |
| `number` (число) | `3`, `0.5`, `-12` (целые и дробные в одном типе) |
| `boolean` (да/нет) | `true`, `false` |

Переменные создают словами `const` (нельзя переназначить) и `let` (можно). Почти везде в проекте используют
`const`: так меньше сюрпризов.

```ts
const word = 'inventory'      // TypeScript сам понял: string
let attempts = 0              // number
attempts = attempts + 1       // можно, это let
// word = 'cat'               // ошибка: const не переназначают
```

Это называется **выводом типа**: писать `: string` вручную не нужно, если TypeScript и так видит значение.

## 1.2 Функция: вход и выход

Функция получает **параметры** и возвращает **результат**. Откройте `src/services/dateKeys.ts`:

```ts
export function localDayKey(value: Date | string) {
  const date = typeof value === 'string' ? new Date(value) : value
  return `${date.getFullYear()}-${String(date.getMonth() + 1).padStart(2, '0')}-${String(date.getDate()).padStart(2, '0')}`
}
```

Разберём по частям:

- `export` — функцию можно импортировать в других файлах (урок 6).
- `function localDayKey(...)` — имя функции.
- `value: Date | string` — один параметр с именем `value`. Тип после двоеточия: это **дата или строка** (знак `|`
  читается как «или»; подробно в уроке 4).
- Тип результата не написан, TypeScript вывел его сам: `string`.
- `typeof value === 'string' ? new Date(value) : value` — условие в одну строку: если пришла строка, превратить её
  в дату, иначе взять как есть. Запись `условие ? если_да : если_нет` называется **тернарным оператором**.
- Обратные кавычки `` ` ` `` — **шаблонная строка**: внутри `${…}` можно вставлять значения.
- `String(date.getMonth() + 1).padStart(2, '0')` — месяц как текст, дополненный нулём слева до двух символов:
  `3` → `03`. Месяцы в JavaScript считаются с нуля (январь = 0), поэтому добавляют единицу.

Результат для 12 октября 2026: `'2026-10-12'`. Зачем это нужно: ключ «местного дня» для серии дней. Он не зависит от
часового пояса UTC, поэтому сессия в 1 час ночи записывается в тот день, в котором человек живёт на самом деле.

### Стрелочные функции

Короткая запись функции со стрелкой `=>`. Откройте `src/services/learningAnalytics.ts`:

```ts
const percent = (correct: number, total: number) => (total ? Math.round((correct / total) * 100) : null)
```

Это то же самое, что `function percent(correct: number, total: number) { return … }`. Если тело — одно выражение,
`return` и фигурные скобки не нужны.

Что делает: если `total` не нуль (`total ?` — нуль считается «ложью»), возвращает процент, иначе `null` (значение
«ничего»). Так делают, чтобы не делить на нуль.

Тип результата здесь `number | null`: либо число, либо ничего. С такими типами работают в уроке 4.

## 1.3 Цепочка методов

Откройте `src/services/contractions.ts`, функцию `plain`:

```ts
export const plain = (value: string) =>
  value
    .trim()
    .toLocaleLowerCase()
    .replace(/[’‘`]/g, "'")
    .replace(/[.!?,;:"“”()]+/g, '')
    .replace(/-/g, ' ')
    .replace(/\s+/g, ' ')
    .trim()
```

Строка `value` проходит конвейер, и каждый шаг берёт результат предыдущего:

1. `.trim()` — убрать пробелы по краям.
2. `.toLocaleLowerCase()` — всё в нижний регистр.
3. Первый `.replace` — любые «кривые» апострофы заменить на обычный `'`.
4. Второй `.replace` — убрать знаки препинания.
5. `.replace(/-/g, ' ')` — дефис в пробел (`well-known` → `well known`).
6. `.replace(/\s+/g, ' ')` — серию пробелов заменить одним.
7. `.trim()` — ещё раз убрать пробелы по краям.

Выражения между слэшами `/…/g` — **регулярные выражения**: шаблоны для поиска в тексте. Флаг `g` значит «заменять везде,
а не только первое совпадение». Пока читайте их как «ищет такие символы», подробности придут позже.

Эта функция — основа проверки ответов: «It's, a cat!» и «it’s a cat» после `plain` становятся одинаковыми
(`it's a cat`). Поэтому такие ответы засчитываются как верные.

## 1.4 Что находит TypeScript

Вызовите функцию неправильно (в игрушечном примере на Playground):

```ts
function plain(value: string) { return value.trim() }
plain(5)          // ошибка: Argument of type 'number' is not assignable to parameter of type 'string'
plain()           // ошибка: Expected 1 arguments, but got 0
plain('cat').foo  // ошибка: Property 'foo' does not exist on type 'string'
```

Три разных ошибки поймано до запуска: неверный тип, не хватает аргумента и несуществующее свойство.

<summary>Ответы (откройте после своих)</summary>

1. `const` нельзя переназначить после создания, `let` можно. В проекте почти везде `const`: значение, которое
   не меняется, не может неожиданно измениться, читать такой код проще.
2. Параметр может быть либо датой (`Date`), либо строкой (`string`). Внутри функции проверка `typeof value ===
   'string'` решает, что делать в каждом случае.
3. В JavaScript месяцы нумеруются с нуля: январь — 0, октябрь — 9. Людям нужно 1–12, поэтому прибавляют единицу.
4. `null`: условие `total ? … : null` ложно при `total = 0`. Так избегают деления на нуль и бессмысленного «0 из 0 —
   NaN%». `null` честно говорит «процента нет».
5. Исходная: `  It’s Cold, today!  `. После `trim` — `It’s Cold, today!`; нижний регистр — `it’s cold, today!`; апостроф —
   `it's cold, today!`; знаки препинания убраны — `it's cold today`; дефисов нет; пробелы одинарные; итог:
   `it's cold today`.
6. Это не разные типы, обе записи дают `string`. Шаблонная строка — просто удобный способ собрать текст из частей
   со вставками.
7. До запуска, пока вы пишете и собираете проект. Браузер получает уже обычный JavaScript без типов. Проверка:
   `pnpm exec tsc -b` (и она входит в `pnpm check`).
